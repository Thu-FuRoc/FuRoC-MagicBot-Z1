# Booster T1 RoboCupLab 分层控制

`RoboCupLab` 的核心设计不是端到端 23 维关节策略，而是分层控制。

## 分层结构

### 高层

高层策略只输出统一动作接口：

- `mode`
- `velocity`
- `direction`

### 低层

低层控制器负责把高层意图翻译成真正的关节动作：

- walk
- dribble
- kick

## 这样设计的价值

1. rule / IL / RL / self-play 共用一套高层接口
2. 低层控制器可以冻结复用
3. 研究重点能放在任务决策，而不是每次都重新学底层动作

## 当前环境入口

主要任务环境在：

- `robocup_lab/envs/booster/t1_env.py`

## 当前平台关注的问题

不是“怎么把一个人形机器人学会站稳”，而是：

1. 怎么做单机射门任务
2. 怎么做 1v1
3. 怎么让高层 planner / IL / RL 共存

## 一句话总结

这条线的重点是“统一高层动作接口 + 冻结低层控制器”的系统设计。
