网络架构改动可能性与对比分析

当前 Z1 locomotion 使用固定的三层 MLP [512, 256, 128]（Origin 官方默认），本文档分析改动网络结构的潜在影响。

当前：512-256-128 · 19 万参数 缩小：256-128-64 · 5 万参数 扩大：1024-512-256 · 100 万+参数 结构改动：LSTM / 非对称 AC / 新激活

0. 当前基线：为什么一直固定用这个网络

原因说明
Origin 官方默认 Isaac Lab + rsl-rl 标配，社区大量实践验证。起步阶段优先跑通默认配置。
容量足够 ~19 万参数对 locomotion（obs~48→action 12）绰绰有余。已训出能跑的模型，说明瓶颈不在网络容量。
调优重点在别处 奖励函数设计（mirror、clearance、deviation）、5 级地形 curriculum、5-phase pipeline 对效果影响远大于改网络。

3. 方向三：结构改动（LSTM / 非对称 AC / 新激活函数）

改动原理预期收益实现难度推荐度
加 LSTM / GRU 让网络有记忆，处理部分可观测（partial observability）——如脚被遮挡、临时失去观测 鲁棒性提升，能应对观测缺失/噪声 高 rsl-rl 不原生支持 RNN，需改框架底层 中期考虑
非对称 Actor-Critic Critic 能看到特权信息（摩擦系数、真实质量、地面属性），Actor 只看传感器。Critic 评分更准 → Actor 学得更快 训练收敛更快，reward 更高；Sim2Real 不受影响（Critic 不部署） 中 需要扩展 obs 空间，修改 env_cfg 添加 privileged obs 推荐尝试
改激活函数
ELU → ReLU / SiLU / Mish		 不同激活函数梯度特性不同 通常差异很小（<2%），不值得折腾 低 改一行配置 低优先
更深但更窄
[256,256,256,256]		 4 层等宽，不同深度策略 理论上更好的特征层次，但等宽结构不如漏斗高效 低 改一行配置 可实验
最值得尝试：非对称 Actor-Critic。社区已广泛验证其有效性，且不影响部署（Critic 不上线）。只需在 env_cfg 中添加 privileged observation（摩擦、质量、地形类型等），rsl-rl 3.0+ 已支持。

结论

为什么一直固定？ Origin 官方默认 + 19 万参数对 locomotion 绰绰有余 + 调优重心在奖励/curriculum
最值得尝试的改动 非对称 Actor-Critic（privileged obs → Critic），不改 Actor 大小，不影响部署，收敛更快
部署阶段优化 模型收敛后试 [256,128,64]，性能不降就用小模型（推理更快、体积更小）
不推荐的改动 单纯扩大网络（浪费算力 + 过拟合 + Sim2Real gap 更大）
