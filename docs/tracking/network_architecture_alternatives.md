# 网络架构改动可能性与对比分析

当前 Z1 locomotion 使用固定的三层 MLP `[512, 256, 128]`（Origin 官方默认），本文档分析改动网络结构的潜在影响。
当前：512-256-128 · 19 万参数 缩小：256-128-64 · 5 万参数 扩大：1024-512-256 · 100 万+参数 结构改动：LSTM / 非对称 AC / 新激活 

## 0. 当前基线：为什么一直固定用这个网络
**** **** **** 

| 原因 | 说明 |
| --- | --- |
| Origin 官方默认 | Isaac Lab + rsl-rl 标配，社区大量实践验证。起步阶段优先跑通默认配置。 |
| 容量足够 | ~19 万参数对 locomotion（obs~48→action 12）绰绰有余。已训出能跑的模型，说明瓶颈不在网络容量。 |
| 调优重点在别处 | 奖励函数设计（mirror、clearance、deviation）、5 级地形 curriculum、5-phase pipeline 对效果影响远大于改网络。 |

## 1. 方向一：缩小网络 `[256, 128, 64]`

仓库内 **throwing 任务已经在用这个架构**，是最现成的对比参照。
**** **** **** **** **** **** **** **** 

| 指标 | 当前 [512,256,128] | 缩小 [256,128,64] | 变化 |
| --- | --- | --- | --- |
| 总参数量 | ~191,000 | ~50,000 | -74% |
| 模型大小 (JIT) | ~1.2 MB | ~0.3 MB | -75% |
| 推理延迟 (单步) | ~0.8 ms | ~0.3 ms | -60% |
| 训练速度 (iter/s) | 基准 | +15~25% | 更快 |
| 表达能力 | 充足 | 可能不足（复杂地形） | 风险 |
| 输入 48→第一层压缩 | 48→512（10x 扩展） | 48→256（5x 扩展） | 信息损失风险 |
| 部署友好度 | 一般 | 很好 | 适合嵌入式 |
| 过拟合风险 | 低 | 更低 | 正面 |

**适用场景：**模型已收敛且要部署到算力有限的板子上时尝试。如果性能不降，直接用小模型部署。 **风险：**带 height scanner（187 维地形数据）的 obs 输入压缩到 256 可能不够。建议先在 flat 地形测试，再过渡到复杂地形。 

## 2. 方向二：扩大网络 `[1024, 512, 256]` 或 4 层
**** **** **** **** **** **** **** 

| 指标 | 当前 [512,256,128] | 扩大 3 层 [1024,512,256] | 扩大 4 层 [1024,512,256,128] |
| --- | --- | --- | --- |
| 总参数量 | ~191,000 | ~780,000 | ~810,000 |
| 模型大小 (JIT) | ~1.2 MB | ~3.2 MB | ~3.3 MB |
| 训练速度 | 基准 | -20~30% | -25~35% |
| GPU 显存占用 | 基准 | +30~50% | +40~60% |
| 表达能力 | 够用 | 过剩 | 过剩 |
| 过拟合风险 | 低 | 较高 | 更高 |
| Sim2Real gap | 正常 | 可能变大（记住 sim 特征） | 更大 |

**不推荐。**Locomotion 任务的天花板不在网络容量。扩大网络只会：训练更慢、显存更多、过拟合风险更高、Sim2Real gap 更大。除非出现 loss 持续下降但 reward 不涨的欠拟合现象，否则没必要。 

## 3. 方向三：结构改动（LSTM / 非对称 AC / 新激活函数）
**** **** **** **** 

| 改动 | 原理 | 预期收益 | 实现难度 | 推荐度 |
| --- | --- | --- | --- | --- |
| 加 LSTM / GRU | 让网络有记忆，处理部分可观测（partial observability）——如脚被遮挡、临时失去观测 | 鲁棒性提升，能应对观测缺失/噪声 | 高 rsl-rl 不原生支持 RNN，需改框架底层 | 中期考虑 |
| 非对称 Actor-Critic | Critic 能看到特权信息（摩擦系数、真实质量、地面属性），Actor 只看传感器。Critic 评分更准 → Actor 学得更快 | 训练收敛更快，reward 更高；Sim2Real 不受影响（Critic 不部署） | 中 需要扩展 obs 空间，修改 env_cfg 添加 privileged obs | 推荐尝试 |
| 改激活函数ELU → ReLU / SiLU / Mish | 不同激活函数梯度特性不同 | 通常差异很小（<2%），不值得折腾 | 低 改一行配置 | 低优先 |
| 更深但更窄[256,256,256,256] | 4 层等宽，不同深度策略 | 理论上更好的特征层次，但等宽结构不如漏斗高效 | 低 改一行配置 | 可实验 |

**最值得尝试：非对称 Actor-Critic。**社区已广泛验证其有效性，且不影响部署（Critic 不上线）。只需在 env_cfg 中添加 privileged observation（摩擦、质量、地形类型等），rsl-rl 3.0+ 已支持。

## 5. 决策流程：什么时候改、改什么
你现在的训练阶段？  │  ├─ 还在 P1–P4 训练中  │ └─ 不改网络。瓶颈在奖励/curriculum，不在容量  │  ├─ 训练收敛，效果满意  │ ├─ 要部署？→ 试缩小到 [256,128,64]，不降性能就用小的  │ └─ 还在优化？→ 试非对称 AC（privileged obs 给 Critic）  │  ├─ Loss 降但 reward 不涨（欠拟合）  │ └─ 可试扩大一层或加宽（罕见，先排查奖励设计）  │  └─ 部署后遇到观测噪声/缺失  └─ 考虑 LSTM / history stacking（中期方向）
